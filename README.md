# Code Dungeon 및 ServerFramework

2023년 12월부터 2024년 7월까지 3명이 개발한 졸업 프로젝트입니다. C++과 DirectX 12를 사용해 게임 클라이언트를 만들고 멀티플레이어 서버를 연결했습니다. 저는 공통 프레임워크, 애니메이션 편집 도구와 서버 통신을 주로 담당했습니다.

- 개발 기간: 2023.12 ~ 2024.07
- 개발 인원: 3명
- 담당: 공통 프레임워크, 애니메이션·장비 부착 도구, 서버 통신
- 기술: C++20, DirectX 12, ImGui, Assimp, FMOD, Boost.Asio, Protocol Buffers, STL
- [시연 영상](https://youtu.be/hQBBsoL_ETs)

## 프로젝트 구성과 담당 범위

[CodeDungeon](./CodeDungeon)에는 클라이언트와 공통 엔진, 편집 도구가 있고, [ServerFramework](./ServerFramework)에는 서버와 공통 세션, 메시지 및 테스트 클라이언트가 있습니다. 저장소에는 팀원들이 함께 작성한 코드가 포함되어 있습니다. 아래에서는 제가 맡은 공통 구조와 도구, 서버 작업을 설명합니다.

교수님께서 제공한 프레임워크와 스마트 포인터를 바탕으로 필요한 기능을 확장했습니다. 스마트 포인터에는 캐스팅과 메모리 풀 연동을 추가했습니다. 유니티 모델 추출 코드도 제공받아 제 애니메이션 데이터 구조에 맞게 수정했습니다.

## 객체 생성과 공통 프레임워크

최상위 공통 객체를 기준으로 Actor, Component, Resource, Scene 등 필요한 기능을 나누었습니다. Create<T>와 CreateNative<T>에 C++20 Concepts를 적용해 생성할 수 있는 타입과 초기화 함수 사용을 컴파일 단계에서 확인하도록 했습니다.

복제가 필요한 객체는 미리 등록한 원형을 이름으로 찾아 복제하고, 위치처럼 객체마다 다른 값은 생성 시 별도로 초기화했습니다. 객체·리소스·렌더링 관리자 등의 역할을 나누고 UGameInstance의 공개 함수로 접근하도록 구성해 팀원이 내부 관리자를 직접 다루지 않고 공통 기능을 사용할 수 있도록 했습니다.

모델·텍스처·음원 파일은 루트 폴더에서 하위 폴더까지 탐색해 폴더 구조와 경로를 보관했습니다. 저장한 이름과 경로로 리소스를 찾고, 편집 도구에서 모델을 선택해 불러오는 데 사용했습니다.

## 메모리 풀과 렌더링

크기별 메모리 풀을 구성해 반환된 블록을 보관하고 다시 할당할 때 사용할 수 있도록 했습니다. 지원하는 최대 크기보다 큰 요청은 일반 할당으로 처리했습니다. 제공받은 스마트 포인터와 STL 컨테이너용 할당기를 풀과 연결했습니다.

DirectX 12에서는 그래픽 명령과 컴퓨트 명령을 구분하고 셰이더와 리소스 연결을 관리했습니다. 모델과 텍스처를 게임 및 도구에서 사용할 수 있도록 구성했으며 팀원들이 공통 기능을 활용해 파티클과 게임 콘텐츠를 제작했습니다.

## 애니메이션과 편집 도구

모델별 애니메이션 목록과 본의 위치·회전·크기 키프레임을 관리하고, 재생 시간에 맞춰 키프레임 값을 보간했습니다. 루트 본의 이전 프레임과 현재 프레임 위치 차이를 구해 피벗과 월드 변환을 적용하고 실제 캐릭터 이동에 반영하도록 했습니다. 이동 적용 여부는 애니메이션별로 설정할 수 있습니다.

ImGui 도구에서 모델과 애니메이션을 선택하고 재생·정지하거나 특정 시점의 자세를 확인할 수 있도록 했습니다. 특정 재생 구간의 속도 배율을 지정하고, 입력이 유효한 구간과 트리거에 따라 다음 애니메이션으로 전환하는 조건을 편집했습니다. 현재 자세와 다음 자세 사이를 보간해 동작이 갑자기 바뀌지 않도록 했습니다.

공격 판정은 본에 부착한 충돌체가 애니메이션을 따라 움직이되, 설정한 시작·종료 구간에서만 활성화되도록 했습니다. 사운드의 재생 시점과 볼륨도 편집할 수 있게 했고, 비슷한 이벤트를 다른 애니메이션에 복제해 필요한 값만 수정하도록 했습니다. 팀원은 이 도구를 사용해 플레이어의 전투 동작을 만들었습니다.

## 서버 통신과 수신 버퍼 오류

Boost.Asio와 Protocol Buffers를 사용해 비동기 송수신을 구성했습니다. 수신 데이터는 헤더의 종류와 크기를 기준으로 구분하고, 패킷이 한 번에 도착하지 않으면 남은 데이터를 버퍼에 보관했다가 다음 수신 데이터와 합쳐 처리했습니다. 공통 수신 처리와 게임 메시지 처리는 분리했습니다.

서버에 접속한 플레이어의 위치와 상태를 다른 세션에 전달하도록 했습니다. 클라이언트에서는 받은 데이터를 처리 목록에 보관한 뒤 NetworkTick에서 게임 객체에 반영해 수신과 상태 갱신을 나누었습니다. 서버 몬스터의 경로 계산에는 팀원이 구현한 A* 길찾기를 적용했습니다.

통신 테스트 중 수신 문자열이 밀리거나 일부가 누락되는 문제가 있었습니다. 버퍼 크기를 늘리고 atomic을 적용했지만 문제가 남아 패킷을 처리한 뒤 남은 데이터를 옮기는 순서를 다시 확인했습니다. 복사 시작 위치가 잘못된 것을 찾아 수정했고, 이후 반복 송수신과 게임 테스트에서 같은 문제가 재발하지 않았습니다.

Windows와 Visual Studio에서 개발했습니다. 두 폴더의 코드는 2024년 공개 원본인 [364a7dd](https://github.com/PTH9043/GraduateProject/commit/364a7ddd7c360cf60e95601ff5668e97c254d1bb)를 기준으로 합니다. 빌드에는 원본 프로젝트의 외부 헤더·라이브러리와 리소스 설정이 필요하며, .gitignore에 지정된 Reference 폴더 등은 별도로 준비해야 합니다.
